## GitHub — ahmadabdallatt11/tevorli

1. Review the security branch/PR. In **Settings → Actions → General**, permit GitHub Actions if appropriate for the repository/billing policy. Use GitHub-hosted ephemeral Ubuntu runners for untrusted PRs, restrict allowed actions to reviewed actions, and keep default workflow token **read repository contents**. Require maintainer approval for outside-collaborator fork workflows where supported. Never send write tokens or workflow secrets to fork PRs. Do not allow PR workflows to create/approve PRs. Do not add cloud/deployment/customer secrets to this workflow. A nonzero paid runner/billing requirement needs explicit approval.
2. In **Settings → Rules → Rulesets** (or **Branches → Branch protection**, depending on plan), protect preview/tevorli and any main/develop/release branches used for promotion. Require PRs, CODEOWNERS review of sensitive files, dismiss stale approvals, block force-push/deletion, and require current-head status **Security gate**. Select the GitHub Actions source after the first real run; verify the exact check label in that run. Require the branch up-to-date if merge queues are not used. Apply to administrators if supported; avoid a permanent bypass. A sole maintainer cannot approve their own PR: appoint a trusted reviewer or explicitly settle the governance model before enforcing approval requirements; do not label self-review as independent. These files alone do not enforce settings; plan/visibility may restrict private-repository rules. Do not buy an upgrade automatically.
3. In **Settings → Advanced Security** or **Code security and analysis**: enable the dependency graph, Dependabot alerts and Dependabot security updates where included/free. The YAML config creates weekly version-update PRs only after it lands on the default branch; it **does not enable vulnerability alerts**. Current alert state cannot be verified here. Enable repository notifications for owners. Do not enable paid Secret Protection/Code Security on a private repo without approval.
4. CodeQL: public GitHub repositories normally support free code scanning. Private repositories need the appropriate already-licensed GitHub Code Security/Advanced Security entitlement. Confirm visibility/entitlement without purchasing anything. Public repositories run CodeQL automatically through trusted repository visibility in the event. For an already-licensed private/internal repository, use this **advanced workflow setup**, avoid running default CodeQL setup simultaneously, and add repository Actions variable **TEVORLI_CODEQL_ENABLED=true** under **Settings → Secrets and variables → Actions → Variables**. It is a non-secret flag. CodeQL upload is explicitly disabled: the job analyzes and gates SARIF locally, then uploads a sanitized summary only, so untrusted PR code has no security-events write token. Native GitHub code-scanning alert publication would require a separately reviewed trusted uploader; it is not enabled here. The final Security gate then requires CodeQL success. If private/internal and unavailable, leave the flag unset and record the gap; do not call it executed. An owner may choose a separate free SAST service only after review, not by silently enabling billing.
5. Check **Actions → TEVORLI Security** on the PR/current SHA: source, application, final gate, plus CodeQL when enabled. Download sanitized artifacts and confirm all expected scans ran. Weekly schedule is Monday 04:23 UTC (07:23 Jordan time), on the default branch only. Scheduled runs may be delayed/disabled by GitHub inactivity/policy. Enable workflow-failure notifications. No green hosted run is claimed from local actionlint alone.
6. Grant native GitHub API access through the platform's scoped connection/network policy if remote PR/check inspection is desired. Do not paste a token in chat. Updating cloud-network drafts is separate from applying/publishing environment settings.
